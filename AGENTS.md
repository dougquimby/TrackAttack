# TrackAttack — agent handoff

Use this repository map before exploring. Treat the code as authoritative when behavior changes; update this guide when architecture or workflows change.

## Scope

- TrackAttack is a Windows desktop music-guessing game. Local-file quizzes are the default; Spotify playlist quizzes are also a supported source, disabled by default and controlled by `EnableSpotifyIntegration`. Preserve the feature switch and keep source-specific behavior appropriately gated, while considering both sources for shared quiz features.
- Prefer presentation-independent quiz rules and services. Keep WPF controls and lifecycle concerns in `Views/`; avoid adding WPF dependencies to `Engine/`, `Models/`, or reusable `Services/`.
- TrackAttack stores its settings, quiz history, and metadata backups under `%APPDATA%\TrackAttack`.
- Settings are written via a temporary file in the same directory before replacing `settings.json`. Missing settings use defaults; unreadable or invalid settings report an error instead of silently replacing the file.

## Project and commands

- Windows desktop music-guessing game: C# WPF, `net10.0-windows`, nullable reference types and implicit usings enabled.
- App project: `TrackAttack/TrackAttack.csproj`; regression tests: `TrackAttack.Tests/TrackAttack.Tests.csproj`; solution: `TrackAttack.slnx`.
- Build: `dotnet build TrackAttack/TrackAttack.csproj`
- Run: `dotnet run --project TrackAttack/TrackAttack.csproj`
- Generate XML API documentation: `dotnet build TrackAttack/TrackAttack.csproj -p:GenerateDocumentationFile=true` (some legacy APIs still report missing-comment warnings). Keep public local quiz contracts documented with XML comments and validate their parameter and reference tags with this build.
- Run regression tests: `dotnet test TrackAttack.Tests/TrackAttack.Tests.csproj`. Tests use isolated temporary settings and history databases; do not point them at real user data.
- Main dependencies: MetaBrainz.MusicBrainz and MetaBrainz.MusicBrainz.CoverArt, TheAudioDB catalog suggestions, Microsoft.Data.Sqlite, NAudio, SQLitePCLRaw, TagLibSharp, and the optional Spotify Web API packages.

## Application map

```text
TrackAttack/App.xaml
  └─ MainWindow                         composition root / embedded navigation
       ├─ HomeView
       ├─ QuizSetupView ── QuizView ── QuizEngine
       │                    ├─ IPlaybackService / NAudioPlaybackService or SpotifyPlaybackService
       │                    └─ ResultsView
       ├─ MetadataView ── LocalMetadataManager
       ├─ SettingsView
       ├─ HistoryView
       ├─ StatisticsView
       └─ SongsView
```

- `MainWindow.xaml.cs` creates the shared local music source and history repository, owns the current `UserControl` and navigation stack, and guards navigation when a quiz is active. The shared header displays the current page title; avoid repeating it inside individual views. Quiz completion replaces the quiz with `ResultsView`; abandoning a quiz calls `Abandon()` and disposes it. It selects Spotify playback only for a Spotify quiz config.
- Each screen is a WPF `UserControl` with XAML in `Views/*View.xaml` and behavior in its `.xaml.cs` code-behind. Follow these existing patterns; there is no separate ViewModel layer currently.
- `SettingsView` groups profile management, library folders, appearance, and integrations/data into tabs. Profile volume is on Profiles; the genre/decade track-count display preference is on Appearance. The active-profile selector and Save Settings button remain visible across tabs. Leaving Settings or closing the app with unsaved edits prompts to save, discard, or cancel; profile operations and volume changes retain their immediate-save behavior.
- Appearance provides a per-profile dark-mode preference, saved with Settings and applied on startup and profile switches. Existing profiles inherit the previous global preference during migration. The global record-celebration preference defaults to on and controls whether results check and display personal and all-profile records. `ThemeManager` swaps the light/dark resource dictionaries in `Themes/`; use matching palette keys and dynamic resources for UI colors so existing views update when the theme changes.
- `QuizSetupView` raises `QuizRequested` with its config, selected songs, and mulligan reserve. `QuizView` owns the quiz engine and playback service, maps engine events to UI, and disposes resources on unload.
- `Engine/QuizEngine.cs` is the quiz state machine. Keep scoring, rotation, timer, and power rules there rather than in view code.
- `MetadataView` presents and stages edits in `MetadataEditEntry` models. `LocalMetadataManager` scans files, validates and writes tags, and creates/restores recovery snapshots. Keep TagLib and filesystem mutation out of the view.
- `Models/` holds quiz, song, result, profile, preset, and metadata models. `Services/` contains local source/playback, answer matching, and catalog suggestion providers. `Data/` contains SQLite initialization and the async history repository. `Settings/AppSettings.cs` owns settings serialization.
- `MainWindow` persists the sidebar collapsed preference plus normal window bounds and maximized state in `AppSettings`; it restores saved placement only when the bounds intersect the current virtual desktop.

## Local library, quiz setup, and presets

- The supported source is local MP3 and FLAC files. `LocalFileMusicSource.ScanDirectory` scans recursively and reads tags with TagLibSharp. Artist selection prefers a nonblank track performer, then a nonblank album artist; `Various Artists` is not used as a track artist. Missing title or artist can fall back to a filename shaped like `Artist - Title`. Windows Explorer's Authors and Contributing artists columns both expose the MP3 performer tag. The metadata editor uses the same tag-based artist selection but does not infer edits from filenames. Unreadable files are skipped in quiz scans.
- Each profile manages one list of music-library folders in Settings. Remove missing checks configured folders and stages confirmed removals for the next settings save; inaccessible folders that cannot be checked are retained and reported. `QuizSetupView` shows those roots and their subfolders in a space-filling checkbox tree; checking a folder applies to its descendants, and folder changes require Scan / Refresh. The source selector and the Scan / Refresh bar remain fixed while the library view scrolls. The folder and decade/year trees have expand-all and collapse-all controls and pass mouse-wheel scrolling to the surrounding page when the tree cannot scroll further. Roots cannot overlap, and directory junctions/symlinks are not traversed. Presets apply saved folder-selection rules to the currently configured roots and warn if the roots differ; history keeps the original roots and rules for replay. `QuizSetupView` builds genre and decade filters, supports the `! Unknown` option for blank genre or nonpositive year, applies inclusive duration filters and optional unique-artist selection, and shuffles eligible songs. It selects the requested song count and retains extras as the mulligan reserve. `SongsView` shows songs matching the current filters.
- A local M3U/M3U8 playlist is an alternative quiz source and does not require configured library folders. It accepts absolute paths, paths relative to the playlist, and local file URIs for MP3/FLAC files anywhere; comments are ignored, duplicate paths are collapsed, and unavailable, unsupported, or remote entries are reported. M3U8 uses UTF-8; M3U also accepts the Windows ANSI code page. Tracks use the same metadata cache, filters, shuffling, deduplication, and local playback as folder quizzes. Presets and last-started setups retain the playlist path; recent-quiz exclusion is scoped to that path. History stores the path and replays recorded tracks even if removed from the playlist, while replacements and mulligan reserves come only from the current playlist.
- Library scans show a wait cursor over quiz setup and report unavailable folders and unreadable tracks while retaining tracks from accessible folders. Missing folder-selection rules remain saved so they can be restored if the folders return; changing an ancestor's selection replaces its retained descendant rules. Selected genres and years with no current matches remain selected and visible as having no tracks, rather than silently broadening the quiz.
- Local quiz scans cache readable track metadata in `%APPDATA%\TrackAttack\library-metadata-v1.db`, separate from quiz history. Unchanged paths are reused when file size and creation/last-write timestamps match; new or changed files are read again, and deleted entries are pruned only from successfully enumerated, included folders. The setup scan shows the number of cached tracks. Cache errors are reported without preventing accessible files from being scanned. Changes that preserve all fingerprint attributes are not detected.
- Local quizzes select distinct title/artist pairs after applying folder, genre, year, duration, and recent-history filters; matching ignores case and surrounding whitespace. Tracks lacking either field remain distinct unless their paths match. The selected tracks and mulligan reserve share this deduplication and the optional unique-artist restriction, so repeated mulligans cannot reintroduce a duplicate.
- Recent-quiz exclusion is optional and off by default. When enabled, it excludes local songs from the configured number of recent quizzes for the active profile and current source/library by path or title/artist, including songs previously replaced by a mulligan when recorded in history.
- Changing the recent-quiz count refreshes matching tracks immediately; overlapping history queries must not let an older response replace the latest selection. Saving unrelated settings preserves unsaved quiz setup choices for the same profile.
- Quiz profiles are named players or groups selected on Home and managed in Settings. Each profile owns its music folders, quiz defaults (timer/clip duration, volume, matching, skip-on-correct, and recent-quiz exclusion), appearance, and optional circular avatar stored as a resized PNG (maximum 256 pixels per dimension) in `%APPDATA%\TrackAttack\ProfileIcons`; profiles without an avatar display their initials in the navigation footer. Source credentials, metadata provider, navigation, and window preferences remain global. Existing settings migrate into a single `Default` profile without losing those quiz preferences. Quiz history stores the profile name, keeps it after a profile is renamed or deleted, and can be filtered by any profile or across all profiles.
- Quiz history can replay a selected quiz using its saved config and recorded track list, or delete an individual quiz and its song results. Local replay scans the saved and current library roots, resolves exact paths first, and otherwise only accepts a unique title/artist match (using album to distinguish duplicates). Original quiz metadata remains the answer for recovered tracks, including any duplicates already in the saved list. When tracks are missing, users can cancel, play the remaining tracks, or replace all missing tracks with eligible songs when enough are available; replacements and mulligan reserves come from the saved library roots, obey saved folder and track filters and, for new history, the unique-artist and recent-quiz exclusion options. They are distinct from the original replay tracks and each other by title/artist. Older history lacks those two options. If no original tracks or sufficient replacements are available, replay is unavailable. The spoiler mode is retained while browsing a history view; in full-blur mode, title/artist are blurred and guesses from other profiles are blurred, while other spoiler modes preserve their title/artist behavior. A horizontal splitter adjusts the relative heights of the answers and details panes. The leaderboard ranks every attempt, including repeat plays by the same profile, for quizzes with the same title, source type, answer mode, and ordered track identities.
- Statistics uses saved local quiz results and defaults to the active profile, with an all-profiles filter. It shows answer accuracy by artist, genre, decade, and month. Each title or artist requested counts as one answer (both count separately in Guess Both); partial answers count, while power penalties do not affect accuracy. The Overview ranks up to three quiz performances, artists, genres, decades, and songs by answer accuracy, then song appearances, then name; songs are grouped by title and artist. Empty quizzes and unknown artist/genre/decade or songs missing title/artist are omitted from highlights. Missing metadata appears as `! Unknown` in breakdowns; replaced mulligan tracks are not scored as separate songs.
- Completed local quizzes celebrate strictly higher answer-accuracy records against all earlier quizzes, separately for the profile and all profiles; the first eligible quiz and ties do not trigger records. High-score records compare quizzes with the same answer mode, song count, and scoring rules. Answer accuracy is independent of point bonuses and penalties.
- The quiz setup uses tabs for the music library, track filters, quiz rules, and powers; saved setups and the matching-song/start controls remain visible across tabs. Genres wrap into columns beside the decade tree, and the rules tab explains the selected timer mode and shows the calculated total-quiz time or starting per-song time allocation beside its inputs, accounting for available matching tracks. Mulligan replacements add time in per-song mode. Validation opens the relevant tab when settings need attention. Each profile's last started setup is saved and restored when opening a new quiz, including the requested song and power counts even if availability reduced the actual quiz; source folders and playlists are reloaded before applying filters. Restoring this snapshot does not select a named preset, so selecting one reloads its current saved values even when it shares the snapshot's name. Named quiz presets are saved in `AppSettings.LocalQuizPresets`. They store the source folders and selection rules, filters, quiz/timer/clip settings, matching options, title/artist point values, hint scrambling mode, powers and penalties, and recent-quiz options. The decade filter expands to individual years; presets and quiz history save selected years, while older decade selections still include the whole decade. No selection includes all years, and `! Unknown` selects missing years. Selecting a preset rescans the configured library and restores its applicable selections; its name is prefilled so saving updates it without retyping, while changing the name saves under a different name. The song-count display preference is also persisted in settings.
- Trace a new quiz option end-to-end: `QuizSetupView` control and preset handling → `QuizConfig` → engine or service behavior → result/history persistence and display.

## Optional Spotify quizzes

- Spotify integration is off by default. `SettingsView` persists the `EnableSpotifyIntegration` switch; when disabled, Spotify controls are hidden and new quizzes require the local library. Changing the switch in Settings updates an already-open quiz setup view when returning to it.
- When enabled, `QuizSetupView` reuses shared quiz options, powers, and presets. Spotify playlists saved to the connected user's account are the selection source; genre filtering and genre hints are disabled because playlist tracks lack genre metadata, while their local selections are retained. Decade and duration filters and optional unique-artist/recent-quiz exclusion remain available. Track years come from Spotify album release dates. Preview clips can constrain clip starts, lengths, and extenders to the available 30 seconds; Spotify Connect uses the full track.
- Spotify's playlist-items API can return 403 for saved playlists the user does not own or collaborate on. Quiz setup shows playlist owners, marks playlists after an actual 403, disables starting for a selected denied playlist, and displays inline, screenshot-assisted copying instructions and collaborator/account guidance. Refreshing retries the selection; a successful load clears its denial marker, and changing clients clears old account-specific markers. `SpotifyPlaylistAccessException` still provides guidance during history replay. Ownership alone does not determine access, and following a playlist does not grant permission to read its items.
- Selecting Spotify checks the connection and available Spotify Connect devices, with a manual recheck in setup. Immediately before a new Spotify quiz starts, setup repeats the live check and blocks starting if no unrestricted device with an ID is available or the connection fails; users can still load playlists while no device is available. A device may be the desktop app or another Spotify Connect device. Availability does not guarantee Premium playback or continued connectivity.
- `SpotifyService` uses browser PKCE authorization. Configure a Spotify developer app and register `http://127.0.0.1:5543/callback`; credentials are stored with the existing settings in `%APPDATA%\TrackAttack\settings.json`. A playlist must be available in the connected account's playlist library.
- `SpotifyMusicSource` pages playlist tracks and maps track URIs for stable history identity. Preview URLs play locally through NAudio when available; tracks without previews use Spotify Connect playback, with the selected output device shown in the quiz. For Connect playback, use the selected playlist as `context_uri` and the selected track URI as the request offset, pass the selected device ID (which activates that device), and verify Spotify reports the requested track playing before starting quiz progress. Serialize Connect start commands and ignore stale song requests so rapid grid selection cannot leave an older request as the final track. A playback failure must leave the quiz usable: show retry guidance, allow Replay or another song selection, and do not pause the engine without a playback recovery path. Connect audio comes from that Spotify device, not the app's local audio stream. Spotify Web API playback control requires Premium and an available playback device. Runtime API/device behavior requires a connected Spotify account and is not covered by the project build.
- Keep playlist APIs and OAuth in `Services/`, source-specific controls gated in `Views/`, and quiz/source metadata in `QuizConfig` and `Song`. Do not change the local-file path when modifying optional Spotify behavior.

## Metadata repair and lookup

- `MetadataView` shows a wait cursor while scanning MP3/FLAC files through `LocalMetadataManager` and stages edits to Title, Artist, Album, Genre, and Year. Before writing, a scrollable confirmation lists every changed field and file, including filtered-out and unselected tracks, with scanned and normalized-to-be-written values; cancel leaves edits staged. Artist edits update the performers tag, not album artist. Unreadable rows are marked non-editable. Before applying changes, the manager saves a recovery snapshot under `%APPDATA%\TrackAttack\MetadataBackups`; **Undo Last Batch** restores the latest snapshot.
- Catalog lookup uses `IMetadataSuggestionProvider`, with the provider selection persisted in settings: MusicBrainz or TheAudioDB. Both providers retry common punctuation/spacing variants of the artist name, and MusicBrainz falls back to a title/album query when artist-filtered searches return nothing. Keep provider-specific API requests behind this interface and feed suggestions into the same staged-edit workflow.
- `MetadataMatchScorer` ranks candidates using title (20%), artist (15%), album (20%), and duration (45%). Neither provider scores genre; album/year/genre details may be unavailable.
- Bulk lookup operates on selected readable rows, processes requests sequentially, and stages matches for review; it does not write files. For a single selected row, the candidate grid initially checks the top candidate's fields and permits one checked candidate per field; staging combines checked fields across candidates. Right-click a candidate row to check or clear its fields, or use the track grid's context menu for selection, copy, and lookup actions. Multi-row bulk lookup stages confident top matches automatically, while the one-request-per-album option stages year/genre to matching readable tracks. Manual candidate staging can also propagate its checked genre/year fields, even from different candidates, to tracks with the same original album and artist. Cancellation stops further work while retaining already staged candidates. The existing apply confirmation, recovery snapshot, and undo flow still governs file writes.
- Keep API calls and matching/mapping rules out of WPF code where possible; preserve the provider contract's independence from any one catalog or UI.

## Engine and playback behavior to preserve

- Quiz modes are title, artist, and both. The setup view allows configuring the points awarded for each answer type: title-only and artist-only default to 2 points, while Guess Both defaults to 1.5 for title and 0.5 for artist. Partial credit is retained. Legacy quiz history without configured weights keeps the former scoring (1 point for single-answer modes and 1.5/0.5 for Guess Both). Power penalties are stored per song and capped by `MaxPowerPenaltyPerSong` and earned points so a song never contributes negative points.
- Answer matching ignores apostrophes and treats `&` as `and` for titles and artists, regardless of the punctuation setting. Attached elided `n` forms such as `Rock'n Me` match `Rock n Me`. Title guesses also ignore the parenthetical labels `(remix)`, `(new)`, and `(new version)` regardless of that setting; other whitespace and parenthetical behavior remains governed by the existing punctuation option.
- Optional near-miss feedback checks a rejected answer on Enter for one spelling edit or adjacent transposition; it does not award credit. Optional quick-guess bonuses award the configured points once per song when all required answers are completed within the cutoff. Active time accumulates across song visits in either timer mode, excludes quiz pauses, and resets for mulligan replacements; clip-only pauses still count. Both options are off by default, stored in presets and history, and bonus awards are saved per song.
- The quiz displays a consecutive-completed-song streak; in Guess Both, both answers are required. Passing or auto-advancing an unfinished song, jumping away from it, timing out, or using a mulligan breaks the streak; wrong typed guesses do not. Revisiting or leaving a completed song does not affect it. Optional star power defaults off, activates after five consecutive completed songs by default, and awards a configurable bonus (default 0.5 points) starting with the next completed song until the streak breaks. While active, the quiz shows a same-height indicator and a theme-aware animated gold background; the normal appearance returns when the streak breaks. Its settings are saved with presets and history, awards are saved per song, and the maximum quiz score includes only attainable streak bonuses. High-score records compare the star-power scoring rules.
- Timer modes are whole-quiz countdown and per-song countdown. Per-song time is tracked independently with a monotonic clock and retained across passes and jumps; pausing the quiz stops it, and only a mulligan replacement gets a fresh allocation. A song whose time expires is marked missed and removed from rotation, with partial credit retained; the quiz ends when no songs remain. Song switches invalidate queued timer ticks so stale callbacks cannot drain the next song's time. Clip start can be fixed or random; the random start assigned to a song remains the same on retries.
- Playback modes are loop, play once and stop, and play once then auto-advance. The playback service raises `ClipEnded`; the engine marshals timer and clip callbacks to its captured synchronization context and prevents them from advancing state while paused.
- If a local track becomes unavailable after scanning, playback reports the failure without stopping the quiz; Replay retries opening it and the player can pass or choose another song.
- Quiz pause pauses the engine countdown and playback together and excludes paused time from quiz duration. Clip-only pause affects playback without pausing quiz time.
- `IPlaybackService.Volume` is normalized per-stream gain and persists in the active profile's `AppSettings.AudioVolume`; the Settings and Quiz sliders use the same value, and NAudio playback must not change Windows master volume. `SeekClip` seeks relative to the designated clip start, clamps to clip duration, and re-arms clip-end handling. Progress UI shows clip-relative and full-song progress; use the service's clip/song position and duration properties rather than seeking the source track directly.
- Correct guesses normally advance immediately; with `SkipOnCorrectGuess` disabled, the clip finishes its cycle first. The song grid can also revisit a fully correct song without changing its score; answers and powers are disabled, and passing returns to the interrupted unfinished song. The per-song countdown is frozen during such a revisit (the whole-quiz countdown continues). Timed-out songs remain unavailable. Tab passes during a running quiz.
- Mulligan replaces the current slot using the preselected reserve. Results and history show all songs replaced in that slot as unscored Mulligan rows; history spoiler controls also hide their titles and artists. Only the final replacement counts toward scoring and replay. Older history cannot recover songs that were not recorded. Extender doubles a song's clip duration and remains in effect if the song returns in rotation. Clip reroll chooses a different random start, retains an extended clip's duration and any clip-only pause, and remembers the new start across retries; it is unavailable when no different start is possible. Its configured count and per-use penalty are saved in presets and history, and usage is recorded with quiz results. Hints randomly reveal enabled, applicable first-letter, scrambled title/artist, genre, exact-year, or album-cover clues; a clue type is shown at most once per song and revealed clues are retained. Clicking cover art opens a resizable, nonmodal window without pausing the quiz; it closes when the song changes or the quiz ends. Album names are shown with cover art only when guessing the song title, not when artist is part of the answer. Album art tries valid Spotify artwork, then a tagged MusicBrainz release ID or high-confidence release search, then TheAudioDB album artwork; each candidate is decoded before use, and unavailable or unsupported images fall back to another available hint.
- Scrambled title and artist hints use the quiz setup's `ScrambleHintsPerWord` setting. It defaults to scrambling each word independently; when disabled, letters are shuffled across the entire title or artist while punctuation and spacing stay in place.
- Ending a quiz fills in unrecorded songs as incorrect, orders all results by their original quiz slot (including mulligan replacements), and raises `QuizEnded`. Keep scoring and rotation out of view code. Dispose timers, playback, and engine resources along the existing `QuizView` lifecycle.

## Persistence

- Settings JSON: `%APPDATA%\TrackAttack\settings.json` (`AppSettings.FilePath`), including profile settings, active profile, global settings, sidebar collapsed preference, and quiz defaults.
- History SQLite database: `%APPDATA%\TrackAttack\history.db` (`DatabaseInitializer.DatabasePath`); `DatabaseInitializer.Initialize()` creates and migrates the schema, including the profile-name field. Metadata recovery snapshots are stored under `%APPDATA%\TrackAttack\MetadataBackups`.
- `IQuizHistoryRepository` exposes async save/list/detail/recent-song/clear operations. Quiz results are saved through the history repository; abandoning a running quiz saves partial results.
- `QuizConfig` is serialized as JSON in `QuizHistory.ConfigJson`; individual song outcome fields are stored in `QuizSongResult`.

## Change guidance

- Keep async repository and catalog calls async from views; use the existing error reporting patterns rather than swallowing failures.
- Keep XAML layout and its code-behind in sync. Unhook or dispose timers, playback, and event subscriptions along the existing lifecycle.
- For settings/history changes, keep all TrackAttack data under `%APPDATA%\TrackAttack`.
- Follow the repository's existing project and UI conventions. Update this guide when architecture, commands, or important workflows change.
